# 饿麻了外卖平台：UDP 协议与订单数据测试

基于 C++、Qt、UDP 和 SQLite 的外卖业务系统，包含用户、商家、骑手和管理员四类角色，覆盖注册、菜品维护、用户下单、骑手接单与订单状态流转。本仓库重点展示服务端协议测试、数据库核对和代表性缺陷闭环。

## 测试结论

| 阶段 | 总数 | 通过 | 失败 | 结论 |
|---|---:|---:|---:|---|
| 原 48 项协议用例 | 48 | 28 | 20 | 存在多类业务与安全风险 |
| 加入 6 项专项后的最终回归 | 54 | 39 | 15 | 2 类缺陷关闭，8 类风险保留 |

测试通过真实 Qt 服务端和 UDP 数据报执行，以协议响应和 SQLite 前后快照核对结果。覆盖注册、菜品、订单、异常报文、状态更新、重启持久性与失败事务恢复；不把未通过项目写成已修复，也不将协议层结果等同于完整客户端 UI 验收。

## 代表性缺陷闭环

1. **单引号名称导致数据丢失**：SQL 字符串拼接在名称包含 `'` 时插入失败，且“先删后插”缺少完整事务保护。改为参数绑定与事务回滚，并通过触发器强制插入失败，验证旧数据仍被保留。
2. **金额小数精度丢失**：字符串转换造成 `123456.78` 被保存为 `123457`。改用 `double` 参数绑定，复测 `0.01`、`9999.99`、`123456.78` 均准确保存。

仍保留的风险包括非法状态流转、负金额、批内重复标识、未认证写入、注册校验、手机号截断、明文密码响应和必填字段校验，因此未判定整体验收通过。


## 复现方式

1. 使用 Qt 6 与 MinGW 构建 `src/TakeawayPlatformService.pro`。
2. 设置 `TAKEAWAY_SERVER_EXE` 为编译后的服务端路径。
3. 可选设置 `TAKEAWAY_TEST_OUT` 和 `QT_RUNTIME_BIN`。
4. 运行：`python tests/udp_regression.py`

测试脚本在独立临时目录启动服务，并生成自己的 SQLite 数据库与 JSON 证据。请勿指向生产数据库或原始项目目录。
